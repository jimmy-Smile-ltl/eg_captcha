## 四、形态与难点

- **没有 y 先验**：搜索空间是整张 300×150，缺口 y 也要估。
- **低分辨率**：背景只有 300×150，拼图块 70×50，Canny 边缘容易断裂或粘连。
- **缺口对比弱**：缺口与周围风景颜色接近，部分缺口只靠形状轮廓可辨。
- **拼图块形状**：凸/凹榫头比矩形轮廓更可信；但辅助图带背景，不是纯 alpha 块。
- **证据缺口**：没有坐标文件，无法从数据层复核源记录；只能看叠加图。

## 五、求解思路

源记录的做法是「边缘结构匹配」：对背景和拼图块做 Canny，再用 NCC 在整图上滑动取峰。缺口颜色不可靠时，形状边缘比像素颜色稳定。

| 步骤 | 做法 | 关键判据 / 参数 |
|---|---|---|
| 1 预处理 | 背景与拼图块转灰度 | 固定 300×150 / 70×50 |
| 2 边缘 | 两侧分别做 Canny | 保留缺口轮廓与榫头 |
| 3 匹配 | 拼图块边缘在背景边缘图上做 NCC | 全图二维搜索 |
| 4 取值 | 取相关峰为缺口左上角 | 峰值不尖锐时需要人工复核 |
| 5 复核 | 看 `solved.png` 的缺口框是否贴合 | 没有坐标文件可对照 |

```text
# 缺口定位（伪代码，对应源方案 Canny + NCC）

bg_edges   = canny(bg)          # 300 x 150
tile_edges = canny(tile)        # 70 x 50

best = (-inf, 0, 0)
for y in 0 .. H - 50:
    for x in 0 .. W - 70:
        score = ncc(bg_edges[y:y+50, x:x+70], tile_edges)
        best = max(best, (score, x, y))

gap = (best.x, best.y)
```

> 这类小图不适合直接 RGB/SSD：缺口偏暗、拼图块带纹理，像素分布差异大；Canny 只保留形状，能把「榫头对榫头」变成主信号。

## 七、失败与边界

| 现象 | 根因 | 证据 | 结论 |
|---|---|---|---|
| 小图边缘断裂 | 300×150 分辨率低，Canny 阈值敏感 | 12 组均为小图 | 边缘图需人工复核 |
| 缺口颜色接近背景 | 缺口偏暗但不一定变色 | `solved.png` 中缺口对比弱 | 用形状而非颜色 |
| 坐标不可机读 | 只输出叠加图，没有 `answer.txt` | 案例目录只有 `bg/aux/solved` | 不能引用具体坐标 |
| 源记录无准确率 | notes 只有「已攻克」 | `meta.solver` | 不能写成 12/12 |
| 无线上记录 | 未做提交闭环 | 无 `evidence` | 离线定位 ≠ 线上通过 |

**边界**：本页只覆盖缺口定位。由于缺少坐标结果文件，本页不提供逐组坐标表，也不把 `solved.png` 上的文字当作答案。
