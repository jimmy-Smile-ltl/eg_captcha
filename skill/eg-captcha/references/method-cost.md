# 方法标签与成本

## 标签

| 标签 | 含义 | 用 LLM？ | 成本特征 | 典型类型 |
|---|---|---|---|---|
| `CV` | 传统视觉：边缘/模板/颜色/几何 | 否 | 最低；量大更省 | slide、jigsaw、rotate、diff-click、area |
| `DET` | 目标检测 / 物体识别 | 否 | 中；需权重/标注 | icon-click、grid |
| `OCR` | 文字识别 / 字形匹配 | 否 | 低-中 | text-click、font |
| `VLM` | 多模态 LLM / 视觉推理 | **是** | 起步最便宜；按调用计费 | 语义点选、空间推理、网格、长尾题 |
| `ASR` | 语音识别 / 说话人分离 | 否（专用模型） | 中 | audio、voice |
| `PROTO` | 协议 / 枚举 / 计算 | 否 | 低 | gobang、token、pow |
| `ACT` | 行为 / 轨迹 / 浏览器交互 | 否 | 低 | 滑块轨迹、按压、无感 |
| `AUDIO` | 音频 DSP / 模板 | 否 | 低-中 | DataDome 音频 |
| `NONE(...)` | 无求解器；括号内是建议路线 | — | — | 未做 |

组合标签用 `+`，例如 `DET+OCR+VLM`、`VLM+ACT`、`CV+VLM`。

## 选型顺序

1. **先看答案空间**：缺口/角度/交换 → 几何或枚举；文字/图标 → 检测/OCR；语义/空间/排序 → VLM；音频 → ASR；无题面 → PROTO/ACT。
2. **几何题优先 CV**：slide、jigsaw、rotate 等用边缘/模板/几何，量大时最便宜。
3. **文字/图标题用混合**：YOLO 检测 + OCR/Siamese 识别，VLM 只对分歧点仲裁；不要一上来全量 VLM。
4. **语义/网格/长尾优先 VLM**：reCAPTCHA/Amazon 网格、易盾 icon-click、空间推理，VLM 不需要训练数据，起步便宜。
5. **音频用 ASR**：Whisper / 说话人分离；注意背景旁白会压过题面。
6. **无题面用 PROTO/ACT**：token/PoW/无感/按压，不要硬套图像模型。
7. **没有求解器时**：建议先试 VLM（无需训练、按调用计费），量大再换 CV/专用模型；在回答中写明这是建议路线，不是已实现。

## 成本模型

- **VLM**：无训练/标注成本，按调用计费；有延迟、非确定性；适合长尾和语义题。
- **CV**：单次成本最低，但要逐类型调参；量大时优势明显。
- **DET/OCR**：需要权重/标注/训练，前期成本高，适合稳定、量大、类别固定的题。
- **ASR**：专用模型推理，成本中等；音频题几乎绕不开。
- **PROTO**：计算/枚举成本极低，但只适用于答案空间小或有接口字段的题。
- **混合**：CV/OCR 先定位，VLM 只对分歧/语义点调用；通常比全量 VLM 便宜，也比纯 CV 稳。

## 示例

- 极验 slide：`CV`（masked Sobel 梯度 + NCC），未用 LLM，单次成本最低。
- 易盾 / 腾讯 text-click：`DET+OCR+VLM`，VLM 只做分歧仲裁。
- reCAPTCHA / Amazon grid：`VLM`，直接读格，无需训练检测器。
- Amazon audio / reCAPTCHA audio：`ASR`，说话人分离 + Whisper。
- hCaptcha 未做类型：`NONE(VLM)`，建议先试 VLM。
- 数美 slide：`CV+ACT`，但服务端轨迹 ML 拒绝，标 `weak`，不要按离线准确率承诺通过率。

## 回答用户时

- 明确说“用了什么方法、是否用 LLM、成本特征、适用边界”。
- 不要只写“已攻克/待审”；那只是状态，不是思路。
- 不要把源记录准确率说成已复核；加“源记录/待人工审查”。
