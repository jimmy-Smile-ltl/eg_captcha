# 00 总论：验证码分类、求解线与证据

> 本文是全库的方法论总纲。具体类型的题面、样本、思路与实测数据见 `cases/<vendor>/<type>/README.md`；厂商索引见 `docs/<vendor>.md`。

## 一、目的与边界

### 文档分层

- **总纲**（本文）：分类法、三条求解线、方法标签、状态与证据口径。
- **厂商索引** `docs/<vendor>.md`：类型总表、代表样本、厂商级结论；不展开算法细节。
- **类型页** `cases/<vendor>/<type>/README.md`：题面、样本图库、形态与难点、求解思路/关键伪代码、结果与审查、失败与边界。详细内容以类型页为准。
- **案例** `cases/<vendor>/<type>/<NNN>/`：`meta.json` + 媒体 + 可选 `answer.txt` / `result.json` / `annotated.png`；统计与状态的事实源。

本库回答三个问题：

1. 这类验证码长什么样、要求用户做什么？
2. 解它需要哪条技术线，难点在哪？
3. 现有求解器的状态与可信度如何？

**覆盖优先**：先把厂商 × 类型收齐，再审查求解器。没有求解器或求解器效果差，不影响样本收录；`sample-only` 是合法状态。

不回答：密钥怎么派生、参数怎么构造、代码怎么写。

## 二、分类法

按“服务端要求用户完成的任务”分四类：

| 大类 | 任务本质 | 典型类型 |
|---|---|---|
| 图像理解 | 在图中定位、识别、比较、排序 | 滑动拼图、点选、网格、旋转、OCR、空间推理 |
| 交互行为 | 生成符合人类特征的轨迹/时序 | 滑块轨迹、曲线绘制、按压、拖拽 |
| 协议令牌 | 完成计算或环境证明，换取 token | PoW、Token/指纹挑战、无感评分 |
| 无题面 | 服务端静默判定，无用户可见题面 | 无感放行、短信上行、无障碍邮件码 |

每个类型再分三层描述：

- **厂商**：谁的实现。
- **交互形态**：用户做什么（拖、点、选、转、输入、按住、无操作）。
- **题面族**：同一交互下的具体题型（如 hCaptcha 的 22 个 prompt 主题）。

## 三、三条求解线

| 线 | 输入 | 核心步骤 | 输出 |
|---|---|---|---|
| 图像线 | 题面图片/帧 | 预处理 → 定位/识别 → 答案生成 | 坐标、角度、字符、格子编号 |
| 交互线 | 答案 + 页面控件 | 轨迹/时序生成 → 事件投递 | 可被服务端接受的操作序列 |
| 协议线 | 挑战响应/页面脚本 | 计算/环境证明 → 令牌获取 → 回放 | cookie/token |

三条线的关系：图像线解决“答案是什么”，交互线解决“怎么操作”，协议线解决“怎么证明”。

### 方法标签与成本

| 标签 | 方法 | 是否用 LLM | 成本特征 | 典型类型 |
|---|---|---|---|---|
| `CV` | 传统视觉（边缘/模板/颜色/几何） | 否 | 最低；量大更省 | slide、拼图、差异点击 |
| `DET` | 目标检测 / 物体识别（YOLO/ONNX） | 否 | 中；需权重/标注 | icon-click、grid |
| `OCR` | 文字识别（OCR/Siamese 字形） | 否 | 低-中 | text-click、font |
| `VLM` | 多模态 LLM / 视觉推理（直接读图） | **是** | **起步最便宜；按调用计费** | 语义点选、空间推理、网格、长尾题 |
| `ASR` | 语音识别/说话人分离 | 否（专用模型） | 中 | audio、voice |
| `PROTO` | 协议/枚举/计算 | 否 | 低 | gobang、token、pow |
| `ACT` | 行为/轨迹/浏览器交互 | 否 | 低 | 滑块轨迹、按压、无感 |
| `AUDIO` | 音频 DSP/模板 | 否 | 低-中 | DataDome 音频 |
| `NONE` | 无求解器 | — | — | 未做（括号内为建议路线） |

**成本判断**：

- **VLM 不需要训练数据和标注**，只要能发图片即可起步，适合语义题、长尾题、网格题；缺点是按调用计费、延迟较高、存在非确定性。
- **CV 在大量重复题上更便宜、更稳定**，但需要逐类型调参。
- **混合最常用**：CV/OCR 先定位，VLM 只对分歧点或语义点调用（如 YOLO + Siamese + VLM 仲裁）。
- 每个案例的 `meta.method` / `meta.method_note` 标注实际路线；厂商索引的类型表与类型页也有“方法”说明。

## 四、类型 × 解法族

| 解法族 | 适用类型 | 关键判据 |
|---|---|---|
| 边缘 + 模板匹配 | 滑动拼图、缺口定位 | 缺口边缘清晰、拼图块有 alpha/轮廓 |
| 亮度/颜色差分 | 半透明缺口、暗填充缺口 | 缺口区域与周围存在稳定色差 |
| OCR | 文字点选、字符识别、音频转写 | 字符可分割、字体不过度扭曲 |
| 目标检测 | 图标点选、网格多选 | 目标类别固定、有可训练/可匹配的模板 |
| 多模态理解 | 语义点选、空间推理、排序 | 需要语义、常识或空间关系判断 |
| 轨迹生成 | 滑块、曲线、按压 | 服务端校验轨迹/时序，而非仅答案 |
| 协议还原 | PoW、Token、加密提交 | 答案正确但提交被拒，需还原令牌链 |
| 无解/高成本 | 服务端行为 ML、强风控 | 离线答案正确、线上稳定拒绝 |

## 五、状态、求解器与人工审查

### 案例状态

| 状态 | 含义 |
|---|---|
| `sample-only` | 只有样本，无可靠结果或结果未纳入 |
| `result-pending-review` | 有求解器输出，等待人工审查 |
| `solved` | 已有最终结果（可含已复核案例）；审查结论另记在 `review`，不写进 `status` |

`documented-only` 是类型级状态，表示无题面媒体、只写文档，不建案例目录。

### 求解器状态

| 状态 | 含义 |
|---|---|
| `none` | 没有撰写求解器（未尝试/仅采集/未完成） |
| `weak` | 有求解器，但准确率低或误报多，参考价值有限 |
| `exists` | 有求解器与源记录，待人工审查 |
| `partial` | 部分进展：图像/答案已解但提交未通，或只完成前置还原/检测 |
| `browser` | 只能靠真实浏览器交互，纯协议不可行 |

### 求解器效果状态（审核驱动）

网站类型页、详情页和卡片显示的效果状态，不是直接读取源目录的准确率，而是结合本库人工审核打分计算：

| 效果状态 | 判定 |
|---|---|
| 无求解器 | 该类型没有求解器，或只有采集样本 |
| 有求解器 | 有求解器，但没有可打分的案例结果 |
| 效果取决于人工审核的打分结果 | 有可审结果，但尚未审完 |
| 几乎完美 | 全部可审案例都打 1（正确） |
| 可以接受 | 全部审完，有 2（部分正确），没有 3（错误） |
| 效果差 | 全部审完，且至少有一个 3（错误） |

`meta.json` 里的源记录准确率仍保留在详情页「源记录准确率」中，只作线索，不直接等同于上述效果状态。

### 人工审查

每个案例的 `meta.json` 有 `review` 字段：

| 字段 | 初始值 | 说明 |
|---|---|---|
| `state` | `pending` / `not-applicable` | 待人工审查 / 无求解器无需审查；审查后为 `pass` / `partial` / `fail` |
| `result` | 空 | 审查结论：`correct` / `partial` / `incorrect` |
| `reviewed_at` | 空 | 审查日期 |
| `notes` | 空 | 审查备注 |

本库不预设求解器准确性。源记录准确率只作线索，不能当作已复核结论。

### 证据等级（有结果的案例）

| 等级 | 含义 |
|---|---|
| `live-pass` | 真实提交被服务端接受（记录日期与方式） |
| `offline-verified` | 离线答案与真值/多信号交叉核对一致 |
| `manual` | 人工标注，未交叉验证 |
| `unverified` | 仅有求解输出，未验证 |

**关键纪律**：离线准确率 ≠ 线上通过率。聚合成功率不得冒充单案例真值。文档中每个数字都要能追溯到案例或来源。

## 六、失败归因

| 根因 | 典型现象 | 处理 |
|---|---|---|
| 图像分布 | 离线分数高，换背景/字体即崩 | 扩样本、换特征、分层评估 |
| 交互检测 | 答案正确，轨迹被拒 | 研究轨迹统计特征，不追求“完美答案” |
| 协议加密 | 答案正确，提交返回错误 | 还原提交链路；无授权则归档 |
| 风控/指纹 | 同一答案，不同环境结果不同 | 区分“验证码失败”与“环境被拒” |
| 服务端不可解 | 多种方法稳定 0% | 记录边界，不反复投入 |

## 七、跨厂商失败档案

以下结论来自源样本 README 与案例记录（实测时间 2026-07 至 2026-11）；具体日期与证据见各类型页（`cases/<vendor>/<type>/README.md`）与厂商索引。

| 案例 | 现象 | 根因 | 结论 |
|---|---|---|---|
| 数美 slide | 模拟轨迹 100% 被拒 | 服务端 ML 轨迹分析 | 纯图像答案不足以通过，需交互线 |
| 数美 text-click | 风格化字体 OCR 0% | 字体/bbox 分布与训练集差异大 | 换识别路线或人工标注 |
| 极验 v4 icon（demo） | 分类模型 0% | 模型图标集与 demo 图标集不匹配 | 需按 demo 图标重建模板 |
| 美团 6 类 | 图像求解完成，线上 0/6 | 提交 `_token` 与轨迹链未打通 | 图像线 ≠ 闭环 |
| HUMAN press-hold | 纯 HTTP `_px3` 被拒 | 缺真实浏览器 `fst-ec` 与解题回执 | 需浏览器级交互 |
| reCAPTCHA | 有时 20 次不弹，有时每次弹 | 出口 IP 信誉 + 查询词 | 触发与脚本拟人度无关 |
| hCaptcha | 样本齐全，无验证答案 | 只采集题面，未做提交闭环 | 统一标 `sample-only` |
| Amazon 音频题 | 旁白压过题面，分离轨偶发失真 | 双人混音 + 背景旁白朗读文章 | 女声=出题人、男声=旁白；F0 认人后用三模型 + 原混音取词；12 组已定两词与双人转录 |
| reCAPTCHA v3 | 无题面，分数只在服务端 | 纯评分 token，一次性、约 2 分钟过期 | 只记录协议形态，不收录 token；无法离线判定 |

## 八、披露边界

**写**：形态、任务、答案空间、识别思路、轨迹/时序原理、验证链路概念、失败原因、成功率与耗时。

**不写**：可运行代码、密钥、签名/加密实现、完整参数构造、可直接复用的绕过步骤。

## 九、术语

| 术语 | 含义 |
|---|---|
| 题面 | 用户看到的挑战内容（图、音频、提示） |
| 答案空间 | 服务端期望的输出形式（坐标、角度、文本、格子编号、轨迹） |
| 闭环 | 从取题、求解、提交到服务端接受的完整链路 |
| 首答率 | 第一次提交即通过的比例 |
| 证据等级 | 结果可信度的分级，见第五节 |
